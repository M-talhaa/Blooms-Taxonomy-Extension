# Extending the action verb inventory of Bloom's cognitive domain

Code, data and models behind the paper *Extending the Action Verb Inventory of Bloom's
Cognitive Domain for Engineering Education with Machine Learning* (Talha, Shi and Qureshi).

The problem is simple to state. People write learning outcomes with action verbs, but the
Bloom verb lists in circulation are short, generic and rarely cover the vocabulary a
discipline actually uses. This repository builds a larger, discipline-specific verb bank
by learning from the verbs that already carry expert labels and applying that model to
verbs mined from engineering literature. It delivers 1,420 accepted verbs carrying 1,647
verb-level assignments, plus the 230 candidates the model declined.

## Start here

If you want to **label verbs**, go to [`production_model/`](production_model/). Nothing
else needs to run.

```
pip install -r requirements.txt
python production_model/classify.py weld debug appraise
```

If you want the **finished verb bank**, open
[`results/Verb List Classified by Model.csv`](results/Verb%20List%20Classified%20by%20Model.csv).
Rows with `Accepted = True` are the bank; the rest are the declined candidates, kept so
the accept/reject behavior stays inspectable.

If you want **every number and table in the paper**, open
[`results/paper_tables.md`](results/paper_tables.md) (each table names the file it comes from;
exact values are in `results/paper_numbers.json`). Section 20 there holds the numbers that only
the response letter quotes (how the bank and the expert agreement changed from the original
submission).

If you want to **rerun the study**, see [Reproduction](#reproduction) below.

## The notebooks

They are meant to be read in order, and they drive the scripts in `revision_pipeline/`
rather than duplicating them. The scripts are the reference: where a notebook output and a
script output differ, the script output is the one the paper reports.

1. **BT 1 - Analysis on core verb**: the labeled core list, its embedding geometry, and
   the centroid and gap analyses reported in Section 2.1.
2. **BT 2 - Data collection**: extracting candidate verbs from the corpus with Stanza and
   filtering them through WordNet.
3. **BT 3 - Model training and classification**: imports `retrain.py` and runs the model
   zoo, calibration, threshold scan and selection.
4. **BT 4 - Validation and reflection**: expert agreement and the structural checks.
5. **BT 5 - Revision analyses**: cross-validation, encoder ablation, held-out evaluation,
   significance tests and sensitivity analyses added during revision.

## Reproduction

The sequence below regenerates every script output in `results/` and `revision_pipeline/`
from the committed inputs (the few notebook outputs, such as Tables 2 to 4, are checked
rather than rewritten). It was run end to end on a copy of the repository without git history
(Windows 10, 8 cores, Python 3.12.10, CPU only); step 19 was added later and run separately (see
the note under the runtime table). The logs are in `results/logs/` and the comparison with the
committed outputs is summarized under [What a rerun should give](#what-a-rerun-should-give).

### One-time setup (needs network)

Python 3.12 and the pinned packages:

```
python -m pip install -r requirements.txt
```

The saved model is a scikit-learn 1.9.0 pickle, so keep that version. The run used the CPU
build of torch 2.13.0.

Then cache the WordNet data and the three sentence encoders once:

```
python -c "import nltk; nltk.download('wordnet')"
python -c "from sentence_transformers import SentenceTransformer as S; [S('sentence-transformers/' + m) for m in ('all-mpnet-base-v2', 'all-MiniLM-L6-v2', 'all-distilroberta-v1')]"
```

Windows (PowerShell):

## Changes in the round-3 revision

The delivered verb bank and the production model are unchanged from the first revision:
`production_model/` and `results/Verb List Classified by Model.csv` are byte-identical, and
the rerun reproduces them exactly. What changed is how the model choice is evaluated,
documented and checked.

- **Matched evaluation.** Cross-validation and the held-out evaluation now evaluate every
  family at its own structural best configuration and threshold percentile, the same
  configuration its structural objective uses. The first revision evaluated every family at
  default settings and P50 (`supervised_eval.py`, new).
- **Held-out criterion over five seeds.** The held-out evaluation is repeated over outer seeds
  13 to 17 and averaged; the first revision used seed 13 only.
- **Selection rule.** The two-stage rule of the first revision is replaced by one stage over
  the same three criteria: among the eligible families above the adequacy floor
  (PenalizedObj >= 0.5), the minimum of the min-max normalized PenalizedObj, CV macro AUC and
  held-out within-one accuracy, highest wins (`select_model.py`, new; `retrain.py` applies it).
  It selects kNN (n = 21, cosine, distance-weighted, P50). On the same inputs the two-stage
  form selects CalibratedSVC; `results/selection/` reports both, together with every
  sensitivity analysis.
- **Eligibility.** Only families with per-level scores calibrated by the out-of-fold empirical
  CDF can run the production pipeline. Legacy kNN (a vote rule with one global cutoff) is
  reported as a structural reference row, with its tuning corrected to rank by the penalized
  objective (`retrain.py` D11).
- **Robustness over the full menu.** SCS weights (500 joint draws and 20 single-weight
  changes), held-out variants, guardrails and penalties, decision margins, alternative
  aggregations and the effect of admitting Legacy kNN, over all eleven one-vs-rest families
  (`robustness.py`, new). The SCS sensitivity summary is now a thin wrapper around it.
- **Generated tables.** Every manuscript table is generated from committed outputs by
  `paper_results.py`, with cross-checks between sources.
- **Bank structure and expert analyses** (`bank_structure.py`, `expert_recompute.py`): both
  density ratios and the primary-domain distribution, gap means of the extended bank next to
  the core, the gap trend in three encoders, a like-for-like comparison with the archived
  original-submission model, exact p-values, baselines, a label-permutation test, per-level
  Fleiss kappa and a threshold sweep.
- **Change from the original submission** (`change_attribution.py`, new): the original-submission
  labels carried over to the normalized candidate pool and compared verb by verb with the delivered
  bank, and refits of each model family on each version of the training core that attribute the
  change in expert agreement to the core and to the model family. These numbers are quoted in the
  response letter.
- **Figures 1 and 2** are regenerated from the audited core with cosine-distance labels
  (`regen_core_figures.py`); the superseded exports are in `legacy/round2/`.
- **Traceability outputs.** `cv_metrics.py` and `methodology_upgrades.py` keep the first
  revision's protocols; their per-level results and McNemar tests now use the production model
  as the reference, the MiniLM and DistilRoBERTa files include the four families added to the
  zoo, and `heldout_results.csv` is written by the script.
- **Hygiene.** `normalize.py` reads the committed raw pool (`raw_candidates_1824.txt`), so a
  fresh clone runs end to end; the unweighted-fit fallback of the row weights is explicit in
  the code and recorded in the outputs; superseded first-revision files moved to
  `legacy/round2/`; `revision_pipeline/paper_results.md` is replaced by
  `results/paper_tables.md`.

## Method in one paragraph

Verbs are embedded with `all-mpnet-base-v2` and classified by one-vs-rest multi-label
models. Raw scores are mapped to [0, 1] through per-level empirical CDFs fitted
out-of-fold, and a verb is accepted at a level when its calibrated score clears that
level's threshold, set by a percentile scan; when two or more levels pass and the highest
calibrated score leads the second by at least 0.060, only the highest level is kept. Model selection never touches the expert data: each
eligible family is taken at its own structural best configuration and judged on three
criteria, the penalized structural objective on the unlabeled candidates, cross-validated
macro AUC on the labeled core, and held-out end-to-end within-one accuracy; the family with
the best worst normalized criterion is selected. That is a k-nearest-neighbour classifier
(n = 21, cosine distance, distance weighting) at the 50th percentile. Full detail, including
every constant, is in the paper and in the headers of `retrain.py` and `select_model.py`.
